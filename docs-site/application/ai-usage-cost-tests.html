How it works

What the tests prove

The tests are the best statement of intended behaviour, so each group below names the rule it protects.

  • Pricing. Cache buckets are priced separately and the no cache baseline bills every input token at the full rate (tests/test_pricing.py:41-57). A batch request halves every component (tests/test_pricing.py:99). A dated snapshot id resolves to the longest matching row, and a model with no row is not priced (tests/test_pricing.py:113, tests/test_pricing.py:173). A free provider prices at zero, and without token counts it is unavailable (tests/test_pricing.py:392, tests/test_pricing.py:408).
  • Estimated rates. A model matched only by a shorter prefix is flagged as estimated, an exact or suffix match is not, and the flag is carried through summed breakdowns (tests/test_pricing.py:548-564).
  • Store. Ingesting twice changes nothing, and a grown file replaces its own rows (tests/test_store.py:158, tests/test_store.py:176). A message split over several records keeps the largest output, and a smaller duplicate never lowers it (tests/test_store.py:260, tests/test_store.py:283). Records that disagree on input tokens keep the first and warn (tests/test_store.py:485). A resumed scan does not delete earlier rows (tests/test_store.py:427).
  • Pipeline. Since and until include their boundary days, and a Codex local time and a Claude UTC time at one instant fall on the same local day (tests/test_pipeline.py:71, tests/test_pipeline.py:104). Every breakdown sums to the grand total (tests/test_pipeline.py:203). Estimated and unpriced models each raise a warning (tests/test_pipeline.py:498-506).
  • Privacy. Each secret pattern is replaced, and the specific pattern wins over the generic assignment pattern (tests/test_privacy.py:56, tests/test_privacy.py:64).
