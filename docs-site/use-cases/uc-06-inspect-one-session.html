UC-06 Inspect one session

What this is

A use case of the subdomain, written from the code. Every step cites the line that does it, so a reader can check the claim in one click.

How to use it

Read the main flow first, then the alternative flows. The rules, terms and diagrams at the end are the ones this use case relies on.

  • Actors: Dashboard reader
  • Maturity: approved

Description

The Dashboard reader opens a session to see its summary, trace, economics and context.

Preconditions

A report with sessions is loaded.

Main flow

  1. The reader selects a session row. web/src/App.tsx:287
  2. The workspace asks for the outcome at once. web/src/SessionWorkspace.tsx:471
  3. A tab's data is fetched when that tab was requested. web/src/SessionWorkspace.tsx:472

Alternative flows

  • At step 3, a failed fetch shows the endpoint did not answer note with the error text. web/src/SessionWorkspace.tsx:561

Postconditions

The workspace shows the selected tab; trace, economics and context are fetched only once requested.

Acceptance criteria

  • A trace breaks into turns by turn id. web/src/TraceTab.test.ts:196

Business rules

  • BR-124 A workspace tab loads its data only when first opened
  • BR-15 Unavailable is never shown as zero
  • BR-16 Unpriced cost stays out of totals
  • BR-24 Outcome notes are saved only when changed
  • BR-25 Automatic rescan every five minutes
